# Pikvew: правила работы

Перед продолжением работы прочитать `PROJECT_STATE.md`: это источник требований,
согласованных решений, текущего этапа и следующих действий. Обновлять его при
смене этапа, существенных решениях, найденных ограничениях и перед завершением хода.
Не считать предложения согласованными до ответа пользователя.

- Общение с пользователем на русском.
- Не использовать queued/async вопросы: консоль пользователя их не показывает.
  Если нужен ответ пользователя — остановиться и задать вопрос обычным сообщением.
- Windows 10/11 x64, WPF, .NET 10. Интерфейс на английском.
- Качество: YAGNI, KISS, SOLID, модульность, DI, Generic Host (IHost).
  Не создавать слои и абстракции без текущей необходимости.
- Покрывать поведение содержательными автоматическими тестами; пользователь
  явно запросил тестовое покрытие. Проверки UI и мониторов также требуют ручной проверки.
- Соблюдать три этапа из PROJECT_STATE.md. Этап 1: только скелет, без проверок.
- Rider MCP использовать для навигации и инспекций. Пользователь явно разрешил
  обычные инструменты для редактирования файлов, dotnet build/test и прочего.
  Подключение к решению Pikvew подтверждено. Этапы 2/3 можно совмещать:
  пользователь разрешил полноценный UI без дополнительного согласования этапа.
- Существенные решения и новые функции согласовывать. Не расширять scope молча.
- Для визуальной проверки небольшого набора (до примерно пяти скриншотов)
  допустима самостоятельная оценка; массовую визуальную проверку просить у пользователя.
- Пользователь разрешил коммиты и push в GitHub из этой репы. Не трогать другие репы.
- Для запуска пользователем при необходимости давать .cmd/.bat, запускаемый двойным кликом.
